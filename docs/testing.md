# 测试说明

> 来源：PROJECT_DOCUMENTATION.md、fix-spec.md、Enterprise General SE Standards.md，仅重编号。

## 1. 项目测试规范

- 单元测试：Service 层核心业务逻辑覆盖。
- 集成测试：Controller 接口端到端测试。
- 安全测试：HMAC 签名、JWT、AES 加解密、SQL 注入、XSS 防御验证。

## 2. 回归测试与验收标准

### 2.1 零缺陷交付门禁

任何修复进入生产前，必须同时满足：

1. **编译与构建**：后端 `mvn clean verify` 通过；前端 `npm ci && npm run build` 通过。
2. **数据库迁移**：Flyway `validate` 通过；在预发全量副本演练；有回滚脚本或前向修复脚本。
3. **测试**：P0/P1 对应回归用例 100% 通过；新增代码单测覆盖率 ≥80%，审批状态机分支覆盖 ≥90%。
4. **安全**：gitleaks 0 命中；OWASP dependency-check 无 CVSS ≥7 未豁免项；SAST 无高危。
5. **可观测**：关键路径有日志、指标、告警；禁止 `catch { return false; }` 类静默失败。
6. **发布**：金丝雀 5% 流量观察 ≥10 分钟，错误率 <0.1%，P95 不劣化，方可全量。
7. **回滚**：数据库变更向前兼容；应用可回滚至上一版本；回滚演练通过。

未满足任一门禁，**阻断发布**。

### 2.2 回归测试与验收

1. **审批端到端**：串行多级链仅末端通过才 `APPROVED`；驳回终态 `REJECTED`；驳回→重提交可续批。
2. **越权**：带 `status:3` body 被拒；越权 `current-task` 403；非超管维护接口 403。
3. **加密/PII**：离职表密文落盘；env 激活下历史密文可解。
4. **数据层**：离职成功；首条插入无主键冲突；离职列表 total 正确；审计写入查询正常。
5. **限流**：`/api/v1` 下超 5/min 被拒；伪造 XFF 不绕过。
6. **CI 门禁**：`mvn test`、`npm run build`、OWASP、gitleaks 真实阻断。
7. **故障演练**：提交后立即宕机，link 不丢；流程结束事件重复投递幂等。

### 2.3 最终交付标准

本规范作为生产修复的唯一执行基线。每个 W 项必须形成：  
**变更单 → 代码/迁移 → 单测/集成/E2E → 预发演练 → 金丝雀 → 全量 → 复盘归档**。  
任何未通过门禁的变更不得进入生产。以零缺陷为目标，以门禁和回滚为保障，以可观测和审计为闭环。

### 2.4 集成测试环境要求

- 需本机 PostgreSQL 与 Redis 运行（集成测试基于真实 PostgreSQL + Redis）。
- 测试库 `work_order_it` 由集成测试自动重建（见 `backend/src/test/resources/it/setup-db.sql`）。
- 数据库密码不再有默认值，运行方式：`mvn verify -Pit -Dit.db.password=<本机密码>`，或设置环境变量 `IT_DB_PASSWORD`（CI 由 secrets/services 注入）。
- Redis 使用 database 1，避免与本地开发库（database 0）数据互相污染。

## 3. 测试分层与上线门禁

### 3.1 测试分层规范

1. 单元测试：核心业务逻辑、工具方法、通用算法必须编写单元测试，保证基础功能可靠。

2. 接口测试：所有对外接口覆盖正向、反向场景，留存完整测试用例。

3. 功能测试：全覆盖业务流程、正常场景、异常场景、边界场景。

4. 兼容性测试：适配浏览器、终端、系统版本、环境差异。

5. 性能测试：核心接口、高频功能做并发、压测、耗时优化测试。

6. 安全测试：覆盖越权访问、注入攻击、XSS、重复提交、令牌劫持等场景。

### 3.2 上线测试门禁（强制）

所有功能上线前必须完成：边界测试、异常测试、并发测试、安全测试，无致命bug、无高危漏洞、无性能瓶颈方可上线。
